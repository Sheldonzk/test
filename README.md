## 2. 技术路线谱系：这三篇处在什么位置

```
传统小视觉模型 / 单域专家
   │   03 ALL-IN-ONE ── 仍属这条线：不靠大模型，靠模块设计与数据集创新
   │
   ├─→ MLLM / VLM 可解释检测
   │        01 Rethinking VLMs ── 对这条线做「冷静的反思」：先诊断，再重构
   │
   └─→ 统一基础模型 + 数据工程
            02 Venus-DeFakerOne ── 把四个域并成一个模型，并把方法论重心放在数据上
```

- **03 是「精工细作」路线**：任务定义创新（多篡改）+ 新数据集（MMID）+ 三个针对性模块。技术上完全不用大模型，工程上最轻量，最容易复现，也最适合作为「我们自己在做的方法类工作」的参照。
- **01 是「先证伪再设计」路线**：论文最有价值的部分不是网络，而是 §3.1 的诊断实验——它明确指出把 CLIP/LLM 塞进 IFDL 流水线未必有用。这是一篇「打破惯性」的论文，适合作为方法论批判的范例。
- **02 是「规模 + 数据工程」路线**：它的贡献重心不在于网络（InternVL2+SAM2 是已有组件的组合），而在于千万级数据构造、闭环难例挖掘、以及一整套数据配比实验。它给的是**经验规律**（scaling law 在 FIDL 不成立、跨域转移由操作级伪影相似性决定）。

## 3. 三条可以串起整场汇报的主线

### 主线一：低层伪影 vs 高层语义，两个世界还没打通

- 01 的实证：CLIP 在真实图与篡改图之间的视觉特征余弦相似度高达 96.3% / 98.5%，说明 VLM 的表征对「真实性」几乎不敏感。
- 03 的应对：用可学习小波把特征拆成 HH / HL / LH / LL 四频带，再用 RK2 二阶求解器生成精确边缘——纯粹往低层伪影上补。
- 02 的应对：动态 VQA 模板（打破「二分类」语义绑定）+ 分割 token 作为 SAM2 空间提示——用语义引导定位，但把真实性判断交给受限词表打分。

**汇报时的一句话**：三篇都在回答同一个问题——「怎么让模型既懂语义又懂伪影」，但 01 认为现有 VLM 做不到、要解耦；02 认为要靠数据和提示设计；03 干脆绕开语义，只做低层。

### 主线二：数据比模型更关键

- 02 用最强反例：给 DeepFake 域额外加 **14M** 张 ScaleDF 数据，DeepFake AUC 反而**下降 4.9%**。结论是「更多数据 ≠ 更好」，关键在配比与操作级互补性。
- 03 的困境也是数据：现有数据集（CASIA / NIST / CoMoFoD）每张图只有一种篡改类型且只给二值掩膜，所以才必须自建 MMID。
- 01 的评测也全是跨数据集泛化（MMTD-Set 训练、8 个数据集测试）。

### 主线三：监督粒度决定任务上限

- 02 的 Table 9：在 Nature 域加入分割监督后，**分类** AUC 平均提升 3.3 个百分点（NIST16 +10.7）。这是「细粒度监督反哺粗粒度任务」的硬证据。
- 01 的核心洞见反过来：把定位掩膜作为 LLM 的**额外输入**（而非输出），能显著提升语言解释质量（GPT-5 评分 1.67 → 2.44）。
- 03 把监督粒度推到极致：像素级**四类**标签（pristine / splicing / removal / copy-move），因为「把三类篡改当一类」正是它要解决的问题。

### 三句话记住三篇

- **02**：FIDL 不缺模型，缺的是数据配比方法论；单域堆数据会让模型变笨。
- **03**：一张图里可能同时有拼接、移除和复制粘贴，把三类当成一类做，谁也做不好。

## 6. 问答预案（我把论文里的薄弱处都列在这里）

**Q1：01 说 VLM 先验没用，可它自己不也用 Vicuna-13B 生成解释吗？**
A：两者的分工不同。01 明确把「检测+定位」交给 ViT+SAM（不用 VLM），VLM 只负责生成语言解释。论文的立场是「VLM 不该管判别，该管解释」——而且解释还需要把掩膜喂进去才做得好。

**Q2：02 的 12.5M 数据里有多少是能拿到的？**
A：AIGC 域 3.6M 里有 1.256M 是私有的；Document 域 2.5M 里有 2.338M（>93%）是私有真实文档；DeepFake 域 3.1M 里有 2.22M 私有。也就是说**公开部分只占约 1/3**，方法的可复现性是这个工作最大的软肋。汇报时要主动说明这一点。

**Q3：02 里 GPT-Image-2-Bench 只有 71 张，95.8% 可信吗？**
A：71 张意味着 1 张图约等于 1.4 个百分点，置信区间很宽，而且它是由 VLM 描述 OpenMMsec 样本后用 GPT-Image-2 重生成构造的，与真实世界分布有差距。建议表述为「在小规模压力测试上明显领先」，不要当成稳固的绝对结论。

**Q4：03 的 copy-move IoU 只有 0.36，是不是说明 CADM 没用？**
A：不是。CADM 让 copy-move IoU 从 0.2829（Baseline）提到 0.3602，**相对提升约 27%**，是三模块里对该类提升最大的。绝对值低说明复制粘贴定位本身很难，而不是模块无效。汇报时强调「相对提升」而不是绝对值。

**Q5：03 的 MIoU 为什么和逐类 IoU 的平均对不上？**
A：我核对过：按定义 MIoU 应该是三个篡改类（不含 pristine）的 IoU 平均值，本文方法的 0.5567 与逐类平均 0.5566 完全吻合，但同表中 SPAN 报 0.2798（三类平均应为 0.2936、四类平均 0.4522）、MVSS-Net 报 0.4872（三类平均 0.3446）、TA-Net 报 0.5337（三类平均 0.4209）都对不上，说明该列在不同行之间可能混用了口径。**建议汇报时只讲逐类 IoU、F1^L 和 AUC^L**，别引用 MIoU。

**Q6：01 声称在跨数据集评测中 7/8 个数据集最优，准确吗？**
A：按 IoU 看是 **6/8**：IMD2020 输给 FakeShield（0.46 vs 0.50），AIGC-Editing 输给 SIDA-13B（0.47 vs 0.53）。如果放宽到「最优或并列」，AIGC-Editing 的 F1 是 0.61 与 SIDA-13B 并列，可以说成 7/8。汇报时用「6 个数据集取得最优 IoU，平均 IoU 领先第二名 8 个点」更稳妥。

**Q7：这三篇的评价指标能直接比吗？**
A：不能。01 用 ACC/F1/IoU/AUC + GPT-5 打分 + CSS + 用户研究；02 用 ACC/AUC + 像素 F1；03 用 IoU^C/MIoU^C/ACC^C/Precision^L/Recall^L/F1^L/AUC^L。而且 03 的像素标签是**四类**，F1 计算口径与二值掩膜不同。跨论文只能做定性对比。

**Q8：如果只能选一篇精读，选哪篇？**
A：看目的。想做方法 → 03（结构清晰、可复现、单卡就能跑）；想做方法论批判 → 01（诊断实验的写法值得学）；想做数据与工程 → 02（数据配比实验设计是一套可复用的思路）。

## 7. 我额外标注的「待核实点」（不建议主动讲，被问到再答）

1. **02 的鲁棒性表存在一处异常跳变**：Table 12 中 Brightness 等级 1.5 的准确率是 50.33，而相邻等级 1.0 / 2.0 分别是 84.59 / 70.36，高亮异常；该异常把 Brightness 一行的平均值从约 80 拉到 70.60。可能是评测或记录问题。
2. **03 的 MIoU 口径不一致**（见 Q5）。
3. **01 的边界情形**：本文方法在 IMD2020 与 AIGC-Editing 上并非最优，正文「7/8」的表述偏乐观（见 Q6）。
4. **02 未开源模型与数据**：正文只给出 GitHub 链接，且核心数据大量为私有，第三方复现难度高。
5. **三篇都未报告多次运行的方差**：01 的 GPT-5/用户研究有分布，但检测定位指标都是单次结果；02 只做了 seed / temperature 的推理稳定性测试，没有训练重复；03 没有随机种子重复实验。汇报时如需强调显著性，要自己补充说明。
